# qwen ↔ DeepSeek Bridge

Мост между **локальной моделью** (qwen2.5:3b через Ollama) и **облачным DeepSeek**.
Локальная qwen разговаривает с пользователем и **сама решает**: ответить своими
знаниями или, если запрос требует свежих/внешних данных (или пользователь сказал
«спроси у deepseek»), — маршрутизировать запрос в веб-версию DeepSeek и вернуть ответ.

```text
Юзер ──► qwen (локальная, Ollama) ──► (знает сама?) ──► ответ
                              │
                              └──(DEEPSEEK: <вопрос>)──► webchat.py ──► DeepSeek (веб) ──► ответ
```

## Возможности

- **Автономная маршрутизация**: qwen сама определяет, когда обратиться к DeepSeek
  (по ключевым словам «спроси у deepseek» или для актуальной информации/новостей).
- **Интерактивный и разовый режимы**.
- **Автоподъём Chromium с CDP**: если браузер не запущен, скрипт поднимает его
  вместе с нужными вкладками.
- **Переносимость**: конфигурация через переменные окружения, без жёстко
  зашитых путей и секретов.

## Требования

- **Ollama** с локальной моделью (по умолчанию `qwen2.5:3b`), API на `localhost:11434`.
- **Chromium** с флагом `--remote-allow-origins=*` и портом `9222`.
- Пользователь должен быть **залогинен** в `chat.deepseek.com` в используемом
  профиле Chromium (например, через Google OAuth). Без активной сессии веб-DeepSeek
  не ответит.
- Python-зависимости: `websocket-client` (для webchat.py).

## Установка и запуск

```bash
# 1. Клонировать или скачать репозиторий
git clone <repo-url> qwen-deepseek-bridge
cd qwen-deepseek-bridge

# 2. Убедиться, что Ollama работает и модель загружена
curl -s http://localhost:11434/api/tags | head

# 3. Запустить мост
./qwen                       # интерактивный режим
./qwen "сколько будет 2+2"   # разовый — qwen ответит сама
./qwen "спроси у deepseek: свежие новости"   # уйдёт в DeepSeek
```

В интерактиве выход — `exit`, `quit`, `выход` или Ctrl+D.

## Конфигурация (переменные окружения)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `QWEN_MODEL` | Локальная модель в Ollama | `qwen2.5:3b` |
| `WEBCAT` | Путь к webchat.py | рядом с мостом |
| `CDP_PORT` | Порт CDP Chromium | `9222` |
| `CHROMIUM_CDP_PROFILE` | Папка профиля Chromium | `~/.config/chromium` |
| `QWEN_EXTRA_TABS` | Доп. вкладки (через пробел) | — |

## Как это работает (кратко)

- **`qwen2deepseek.py`** — главный мост. Шлёт реплики qwen с системным промптом-посредником
  и ловит маркер `DEEPSEEK: <вопрос>`. При маркере вызывает `webchat.py`.
- **`webchat.py`** — работает с открытой вкладкой `chat.deepseek.com` через CDP:
  вставляет вопрос в поле ввода, жмёт Enter, ждёт и извлекает ответ ассистента,
  затем возвращает его.
- **`qwen`** — bash-обёртка: поднимает Chromium с CDP, если тот не запущен, и запускает мост.

## Важные особенности / ограничения

- **Скорость**: на маломощных платах (например, Orange Pi Zero 3W) qwen генерирует
  медленно (~0.3–4 ток/с). Первый запрос может занимать её загрузку в память (1–3 мин).
- **CDP 403**: без флага `--remote-allow-origins=*` Chromium отклоняет WebSocket-подключения.
  Обёртка всегда передаёт этот флаг.
- **CDP нельзя включить на уже запущенный Chromium** — флаг считывается при старте.
  Если открыт Chromium без CDP — закрой его перед запуском `qwen`.
- **Активная сессия DeepSeek обязательна** — для веб-версии нужен вход в профиле.

## Безопасность

В этом репозитории **нет** API-ключей, паролей, токенов или служебных аккаунтов.
Локальный CDP-порт и профиль Chromium — локальная конфигурация пользователя.
Не публикуйте в форк/README свои реальные креды.

## История изменений (Changelog)

**2026-08-23 — v0.5 · Бинарный роутер вместо пересказа (совместно с Джарвисом)**
- **qwen = чистый маршрутизатор**: отвечает только `{"route":"self"}` или `{"route":"deepseek"}`
  (JSON, `temperature=0`), БОЛЬШЕ НЕ формулирует и не пересказывает вопрос.
- **В DeepSeek уходит сырая реплика пользователя**, очищенная регэкспом от командных
  префиксов ("спроси у deepseek" и т.п.) — вопрос больше не искажается моделью
  (раньше «завтра»→«сегодня»), не появляется пересказ от третьего лица.
- `webchat.py`: извлечение ответа стабильнее против замещения старого ответа DeepSeek
  в DOM (не хватает старый ответ, если тот остался в вкладке).
- Рекомендовано Джарвисом (Pi 5): разделить «кто отвечает» (роутер) и «что спрашивать» (сырой текст).

**2026-08-23 — v0.4 · Игнорирование thinking-блоков DeepSeek при извлечении ответа**
- Исправлен глюк: DeepSeek рендерит свои **внутренние рассуждения** (класс `ds-think-content`)
  в тот же контейнер `.ds-assistant-message-main-content`, что и настоящие ответы. Они могут
  идти ПОСЛЕ ответа и попадать в «последний элемент», из-за чего мост возвращал старый/мусорный
  текст (например, «ответ на дыню» вместо нового).
- Теперь `webchat.py` **отфильтровывает предков с `ds-think`** и берёт последний НАСТОЯЩИЙ ответ.
  Проверено на живом DeepSeek: «какой океан омывает Бразилию» → корректный ответ, без мусора.

**2026-08-23 — v0.3 · Надёжная маршрутизация и контекст диалога**
- Добавлена **память диалога**: история (user/assistant) накапливается и передаётся в qwen,
  поэтому короткие реплики («а дыня?») правильно понимаются в контексте
  (например, после «какого цвета арбуз?»).
- Распознавание маркера стало **толерантным к мусорным токенам** (раньше строго `DEEPSEEK:`,
  сломанные `ARBUZ:`/`ARBER:` игнорировались). Теперь ловится любой маркер `СЛОВО: вопрос`.
- Добавлен **fallback**: если qwen отвечает «не знаю/уточните/не уверена» — запрос всё равно
  уходит в DeepSeek.
- История ограничена последними 4 парами (защита от переполнения контекста маленькой модели).

**2026-08-23 — v0.2 · Исправление определения завершения ответа**
- `webchat.py`: больше не полагаемся на *счётчик DOM-блоков*. DeepSeek иногда
  дописывает новый ответ в уже существующий элемент, из-за чего счётчик не менялся
  и скрипт «не попадал в диапазон», крутясь впустую до 180 с.
- Теперь ответ считается готовым по **стабильности `textContent`** последнего
  элемента (текст не меняется ~4 с подряд). Это корректно ловит и «новый блок»,
  и «дописывание в тот же элемент», экономя время до ~3 минут на запрос.
- Переход с `innerText` на `textContent` — меньше мусорных артефактов (числа сносок).

**2026-08-23 — v0.1 · Первоначальный выпуск**
- Мост `qwen2deepseek.py` (локальная qwen ↔ облачный DeepSeek).
- `webchat.py` — отправка вопроса в веб DeepSeek через CDP.
- `qwen` — bash-обёртка с автоподъёмом Chromium (CDP + `--remote-allow-origins=*`).
- Конфигурация через переменные окружения; README; `.gitignore` без секретов.
